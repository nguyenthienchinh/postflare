# Postflare

Self-hosted social scheduler on Cloudflare Workers (Hono + D1 + R2 + Workflows + Images), React app in `src/`.

- `npm run dev` runs Vite with the Cloudflare plugin (local Worker, D1, R2, Workflows). `npm test` runs vitest (provider tests mock `ctx.fetch`). `npm run typecheck` before committing.
- Providers live in `worker/providers/<id>.ts` and implement the `Provider` contract in `worker/providers/types.ts`; follow `docs/provider-brief.md`. Always use `ctx.fetch` via `http.ts` helpers, never global fetch, and never buffer media: use `ctx.media.rangeStream` / `stream` / `mediaBody` (zero-copy). Must fit the Workers Free plan: ~10ms CPU and ≤40 fetches per provider call (see "Free plan budget" in the brief, `providers/budget.ts`).
- Multi-tenant: every request handler must scope accounts/posts/post_logs/media/upload_links/api_keys/oauth_states queries by `workspace_id` (`wsId(c)`; ids of other workspaces → 404, never 403) and guard routes with `requirePermission("posts.write")` / `requireInstancePermission(...)` from `worker/lib/auth.ts` (catalog: `worker/lib/permissions.ts`). Unscoped `getPostRow`/`getAccountRow` are for workflows and cron only. Isolation/permission tests: `test/workers/` (`@cloudflare/vitest-plugin`, real D1, storage isolated per test file).
- Schema changes: add a new `migrations/000N_*.sql`; `worker/lib/migrate.ts` applies it automatically on first request.
- Publishing runs in `worker/workflow.ts`. The request that creates a post must be marked `commit: true` (see docs/provider-brief.md): an ambiguous failure there moves the post to `needs_check` instead of retrying, so nothing is ever posted twice. One cron trigger `*/5` (Free accounts share 5 triggers across all Workers); `cronJob()` in worker/index.ts picks the job by UTC minute: :00/15/30/45 publishing safety + refresh, :05/20/35/50 analytics, 03:10 daily cleanups/media sweep — each job must stay under 50 D1 queries (test/workers/publish.test.ts counts them).
- `cli/` is the `postflare` CLI (Node 20+, built-ins only, no runtime deps): keep `cli/src/types.ts` in sync with `shared/types.ts` when API shapes change. `npm run cli:build`, `npm run cli:typecheck`; tests in `cli/test` (vitest project "cli"). `skills/postflare/SKILL.md` documents it for agents; `cli:build` embeds it into the generated `cli/src/skill-content.ts` (`pf skill install`; a test fails when it is stale).
- `wrangler.jsonc` stays generic (no routes/vars); personal deploy settings go in the git-ignored `wrangler.local.jsonc` (picked by `vite.config.ts`, or `WRANGLER_CONFIG`). `npm run cf-typegen` reads `wrangler.jsonc` only.
- Versions: server in root `package.json` (tags `v*`), CLI in `cli/package.json` (tags `cli-v*`), bumped only by release-please PRs (docs/RELEASING.md). Use Conventional Commit messages (`feat:`, `fix:`, `!` for breaking). `shared/version.ts` has the build version (Vite `define`, `build-info.ts`) and `API_VERSION`: bump it with `cli/src/compat.ts` on breaking REST changes.
- Playbooks: built-ins are `playbooks/*.md` (strict frontmatter + seven sections, bundled by `worker/lib/playbooks.ts`, validated by `test/playbooks.test.ts`; see CONTRIBUTING "Writing a playbook"). Custom ones live in D1 with immutable versions (`playbook_versions`); posts carry `playbook_id`/`playbook_version`/`variant`. `GET /api/playbooks/stats` must stay one aggregate query.
